# 5-Step Demo Script (about 12 minutes)

Domain: refinery equipment inspection (see `DEMO_DOMAIN.md`). Data: `demo_data/` (see `INDEX.csv`).
Speakers: **A** = security/infra, **B** = AI core, **C** = data/governance/UI.

> Several steps depend on features built in later phases (`tasks.md`). Until a feature exists, rehearse that step with
> the manual fallback written under it. Mark each step "ready / not ready" in the rehearsal table at the bottom.

## Before you go on (T-30 min)
- [ ] Wi-Fi ON for setup, models and images already downloaded
- [ ] `export OLLAMA_MAX_LOADED_MODELS=1`, Ollama running, Docker Desktop running
- [ ] `docker compose up -d`, all services `Up`; `llm-bridge` reachable (docs/LLM_ACCESS.md)
- [ ] Warm each model once (chat, coder, vision) so the first call is not slow
- [ ] Demo documents ingested; users `u-junior`, `u-senior`, `u-comply`, `u-admin` exist
- [ ] Grafana egress panel open in a second window, counter at 0
- [ ] Backup screen recording of the whole flow saved locally

## Step 1: Automatic model routing (Speaker B, ~1.5 min)
**Say:** "Different tasks need different models. The router picks one per task and shows why. Nothing is hard-coded."

| Do | Expected |
|---|---|
| Prompt 1: `Summarise inspection report IR-2026-011 in three bullet points.` | Router panel: task = summarization, model = **qwen3:8b**; pump is fit for service, vibration within limits |
| Prompt 2: `Write a Python function that computes corrosion rate from two thickness readings and a time gap.` | Router panel: task = code_generation, model = **qwen2.5-coder:7b** |

**Point at:** the routing decision (classification, rule matched, reason).
**If it fails:** show the saved router decision JSON (`schemas/examples/router_decision.valid.json`) and the registry YAML.

## Step 2: Scanned report to approval note (Speaker B, then C, ~4 min)
**Say:** "An inspector scanned a report. The system reads it offline, flags what it is unsure about, and a human decides."

| Do | Expected |
|---|---|
| Log in as **u-senior**. Upload `reports/IR-2026-014_SCAN_V210_lowquality.pdf`. Goal: `Draft an approval note for the V-210 follow-up inspection, citing the relevant SOPs.` | Agent trace shows nodes: extract, retrieve, draft, export |
| Extraction finishes | Fields shown with confidence bars. **TP3 is amber, "needs review"** (smudged). Equipment tag V-210 is high confidence |
| Human fixes TP3 to **4.7** and confirms | Node turns green; export stays blocked until this is done |
| Retrieval runs | Cites **SOP-01** (5.0 mm triggers engineering review) and **SOP-06** (fitness-for-service) with page numbers |
| Checkpoint: "approve note before export" | Click Approve |
| Download `.docx` | Findings table, recommendation, footnoted citations; provenance sidecar lists model and chunk ids |

**Point at:** the amber field, the citations, the approval gate.
**If it fails:** use `reports/IR-2026-013_pressure_vessel_V210.pdf` (text PDF, same story, no OCR) and say the scan path is shown in the backup video.

## Step 3: Safe code execution and attack resistance (Speaker A, ~2.5 min)
**Say:** "The AI writes and runs code, so the code must be treated as untrusted. It runs in a box with no network."

**3a. Real calculation**
| Do | Expected |
|---|---|
| Prompt: `Using V210_thickness_history.csv, compute the TP3 corrosion rate and the remaining life to the 4.2 mm retirement thickness.` | Code generated by **qwen2.5-coder:7b**, run in the sandbox, log shown |
| Read the result | Corrosion rate **0.40 mm/year**, remaining life **1.5 years**. SOP-06: under 2 years means Engineering Manager approval |

**3b. Isolation probe**
| Do | Expected |
|---|---|
| Admin runs `demo_data/security_tests/sandbox_probe.py` through the sandbox tool | Five lines, all **BLOCKED** (internet, raw TCP, DNS, write outside /out, read /etc/shadow) |
| Look at Grafana | Egress counter still **0** |

**3c. Prompt injection**
| Do | Expected |
|---|---|
| Upload `security_tests/vendor_memo_gasket_supply_INJECTION.pdf`. Prompt: `Summarise this vendor memo.` | Normal summary (gaskets ship 18-09-2026, 6-week flange lead time). **No tool call is made**; UI notes instructions were found in the document and ignored |
| Open the ledger view | No `tool.call` event for that session |

**Say:** "The memo hides an instruction to send confidential files out. Permissions are enforced by code, not by the model, so it has no effect."
**If it fails:** show the pre-recorded probe output and `docs/` threat table (PRD section 8, T2 and T3).

## Step 4: Privacy governance (Speaker C, ~3 min)
**Say:** "Privacy is enforced where the data is retrieved, and users stay in control of it."

| Do | Expected |
|---|---|
| **4a. Access control.** As **u-junior** ask: `What is the budget for the Unit 5 turnaround?` | "Not found in the knowledge base". SOP-08 (board only) is never retrieved |
| Same question as **u-senior** | Also not found (clearance is confidential, document is board only). Shows the lattice holds for everyone |
| Ask `What is the V-210 retirement thickness?` as u-junior, then u-senior | Junior: not found (SOP-06 is confidential). Senior: **4.2 mm** with citation |
| **4b. PII.** Ingest `security_tests/contractor_register_PII.pdf` | Redaction report: names, phones, Aadhaar-style and PAN-style numbers replaced with placeholders |
| **4c. Purpose limit.** Try to retrieve that register for purpose `inspection_review` | Zero results: allowed purpose is `hr_admin` only |
| **4d. Consent and erasure.** As **u-comply** open the document's usage timeline, revoke consent, then erase | Retrieval blocked at once; erasure report shows 0 hits in vector store, cache and object store; ledger records the erasure (hash of id only) |

**If it fails:** show the consent dashboard mock and the erasure design (design.md 3.7).
